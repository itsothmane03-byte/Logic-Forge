# Argument workbench

Scope: Home, Daily Forge, practice selection, and shared visual tokens/chrome.
Mode: Operate. The owner delegates direction and implementation and explicitly
prioritises avoiding a playful, game-like feel.

## Direction contract

THESIS: Let people examine a real argument immediately. Replace the marketing
hero, feature parade, floating demo, and generic tile wall with a working entry.

OWN-WORLD: Crisp neutral reading fields, ink rules, retained orange eye and
primary action, restrained petrol secondary structure, tighter corners. Light
and dark remain real theme variants, without a permanently dark Daily panel.

STORY: Try one argument, see why, then open the shared Daily Forge or select a
specific skill. Preferences come after the activity choice and stay optional.

FIRST VIEWPORT: Concise title, central real argument and verdict controls, Daily
challenge alongside with actual progress. On mobile the two regions stack in a
clear reading order. Signature: a connected Read / Decide / Understand path
changes with the actual demo state; ten Daily nodes reflect checked answers.

FORM: Grounded candidate 3, proof/path diagrams, among scientific correction,
conversation, proof paths, visual perception, museum catalogues, transit signs,
and training scorecards. seed:988037c2a9a26887.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Design judgment

The high-density challenger is declined: worse beginner identification and
clarity; retain its discipline of meaningful information per region. Airport
wayfinding is competitive on clarity: retain one unmistakable next action.
Ticket-wallet, software-manual, mascot-roster and data-sublime directions are
declined on identification and clarity; retain truthful progress states,
consistency, recognisable entry points and exact alignment respectively.
These are system disciplines, not imported decorative motifs.

Code first: this is a working app surface. No generated raster is needed for
the product mechanism. Existing exercise truth and compatibility remain binding.
