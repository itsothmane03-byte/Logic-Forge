# Fallacy Forge — Technical spec

## Stack (keep it small)
| Area | Choice |
|---|---|
| Build | Vite (latest stable) + TypeScript (strict) + Preact (`@preact/preset-vite`) |
| State | `@preact/signals` |
| Router | Tiny hand-written hash router (GitHub Pages friendly) |
| Styles | Plain CSS with custom properties (tokens from UI-SPEC); no CSS framework |
| Icons | `lucide-preact` (tree-shaken) or hand-written SVG components |
| Fonts | `@fontsource-variable/inter`, `@fontsource-variable/bricolage-grotesque` (self-hosted, so offline works) |
| PWA | `vite-plugin-pwa` (autoUpdate, precache everything, manifest from `public/brand` icons) |
| Tests | Vitest + jsdom + `@testing-library/preact` |

Other rules:
- Vite `base: './'` so the build works at any path.
- Pin exact dependency versions; commit the lockfile.
- No runtime network calls at all.

## Content pipeline
`npm run content`:
1. **Validate.** Read `content/fallacies/*.json` and `content/items/*.json`, and enforce CONTENT-SPEC §4. Exit non-zero with a readable list of errors.
2. **Build.** Write `src/data/bank.json`:

```ts
{
  version: string,              // date of build
  fallacies: Fallacy[],         // sorted by family order, then name
  items: Item[],                // sorted by id
  families: { id, label, order }[]
}
```

Flags:
- `--fixtures` reads `content/fixtures/` instead (dev only).
- `--allow-partial` skips the "all 38 / exactly 8 per fallacy" completeness checks while content is still being written. Every other rule still applies.

## Engine rules
### rng
- `mulberry32(seed)`; `seedFrom(string)` uses a FNV-1a hash.
- A deterministic `shuffle(array, rng)`.

### Daily Forge (`daily.ts`)
- `dateKey`: local `YYYY-MM-DD`. Daily number = days since 2026-10-20 (inclusive) + 1.
- 10 items, deterministic from (dateKey, bank items sorted by id):
  - 8 flawed items from 8 **distinct** fallacies, with difficulty mix 3×d1, 3×d2, 2×d3;
  - 2 sound items;
  - shuffle the order with the same rng.
- The same date and bank always give the same set. Different dates almost always differ (test it).

### Practice (`select.ts`)
- 10 items. Fallacy weight by Leitner box: box1 = 5, box2 = 3, box3 = 2, box4 = 1, box5 = 0.5.
- Never-seen fallacies count as box1, but beginners first: weight ×1.5 for beginner-level fallacies when total attempts are under 30.
- 2 of the 10 items are sound.
- Never repeat an item seen in the last 40 attempts (if the pool allows), and never show the same fallacy twice in a row.

### Focus on X
- 5 flawed items of X;
- 2 flawed items from X's confusables;
- 2 sound items resembling X (or any sound items if not enough);
- 1 more flawed item of X;
- shuffled.

### Review
- Items whose latest attempt was partial or wrong, most recent first, up to 10.
- Disabled when empty.

### Distractors (`distractors.ts`)
- 4 options: the correct fallacy, plus up to 2 from its `confusableWith` (in order), plus random fallacies from the same family, then any family, until there are 4 unique options.
- Shuffled with a seed from (sessionSeed, itemId).

### Scoring (`score.ts`)
- **Flawed item:** `correct` if picked flawed and the right name; `partial` if picked flawed with the wrong name; `wrong` if picked sound.
- **Sound item:** `correct` if picked sound; otherwise `wrong`.
- Summary score = number of correct.

### Mastery (`mastery.ts`)
- One Leitner box (1–5) per fallacy, applied only to the item's TRUE fallacy (flawed items):
  - correct: box + 1 (maximum 5);
  - partial: box − 1 (minimum 1);
  - wrong: box = 1.
- Sound items don't change boxes; track `soundStats { seen, correct }`.
- Mastery % = (box − 1) / 4. "Mastered" = box 5.
- Track `stats[fallacyId] = { seen, correct }`.

### Streak (`streak.ts`)
- Consecutive local days with at least 1 answered question, counting back from today.
- If today has none yet, count back from yesterday. Also track the best streak.

### Storage (`storage.ts`, localStorage key `fallacyforge:v1`)
```ts
{
  version: 1,
  settings: { theme: 'system' | 'light' | 'dark', showDefinitions: true },
  onboarded: false,
  boxes: Record<string, 1 | 2 | 3 | 4 | 5>,
  stats: Record<string, { seen: number, correct: number }>,
  soundStats: { seen: number, correct: number },
  attempts: { itemId: string, outcome: 'correct' | 'partial' | 'wrong', at: number, mode: string }[],  // keep last 500
  days: Record<string /* YYYY-MM-DD */, number /* questions answered */>,
  daily: Record<string /* YYYY-MM-DD */, { itemIds: string[], answers: Outcome[], done: boolean }>,  // resume support
  sessions: { mode: string, at: number, total: number, correct: number }[],  // keep last 60
  bestStreak: number
}
```
- Save after every answer.
- Corrupt or missing data falls back to defaults without crashing (try/catch).
- Export downloads the JSON. Import validates the shape and version before replacing the data.

### Share (`share.ts`)
- Builds the share text from UI-SPEC.
- `navigator.clipboard.writeText`, falling back to a textarea plus execCommand. If both fail, show the text in a dialog.

## Quality gates (CI must pass)
- `npm run typecheck`: `tsc --noEmit`, strict.
- `npm run content`: validate and build; on real content with no partial flag.
- `npm test`: Vitest, covering:
  - rng determinism; daily determinism and composition;
  - distractor uniqueness and confusable priority;
  - all scoring and mastery transitions;
  - streak edge cases (midnight, gaps);
  - storage corruption fallback and import validation;
  - the content test runs the validator on the real bank;
  - one rendered session flow: spot flawed, then name, then feedback, then continue.
- `npm run build`: no warnings that matter.
- Bundle check: main JS under 150 KB gzip, excluding `bank.json`.
